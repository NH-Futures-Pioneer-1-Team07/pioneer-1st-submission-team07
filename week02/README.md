## 1. 과제 요약

**과제:** NH선물 Open API로 국내 선물·옵션 상품 하나에 대한 규칙 기반 전략을 구현하고, 실제 실행 기록으로 결과를 분석.
평가 관점은 전략 실행·API 작동·결과 분석(손실 포함)·오류와 개선·재현성.

**현재 상태:**

- 제출 전략: 삼성전자선물 역매매 전략.
- 백테스트: 슬리피지 0틱·1틱 각 1회 실행 완료. 기록은 `results/`에 반영.
- 모의매매: NH 모의계좌에서 운용 중. 종료 후 결과를 6절에 추가.

## 2. 실행 방법

터미널 2개(백엔드·프론트엔드)와 데스크톱 브라우저 필요. 아래 명령은 모두 코드 저장소 기준.

### 2-1. 사전 준비

| 항목 | 준비 내용 |
| --- | --- |
| uv | 설치(`brew install uv` 등). Python 3.12 이상은 uv가 자동 설치 |
| Node.js | 22.12 이상, npm 포함 |
| NH선물 키 | 국내 모의투자 계좌 개설 후 Real HTS **[6128] REST API 신청**에서 **국내 모의투자용** APP Key·APP Secret Key 발급 |

### 2-2. 코드 내려받기

```bash
git clone --branch dev https://github.com/NH-Futures-Pioneer-1-Team07/pioneer-1st-code-team07.git
cd pioneer-1st-code-team07
```

개발 중인 작업 폴더가 있으면 보존하고, 별도 위치에 내려받아 실행.

### 2-3. 설정

```bash
cp backend/.env.example backend/.env
```

`backend/.env`에 발급받은 키 입력. `NH_APP_KEY`·`NH_APP_SECRET` 앞의 `#`를 제거. 이 제출 폴더의 [.env.example](.env.example)은 같은 항목을 `#` 없이 정리한 템플릿이며, 복사해 써도 동일.

```dotenv
TRADING_ENV=mock
NH_APP_KEY=발급받은_국내_모의투자_APP_Key
NH_APP_SECRET=발급받은_국내_모의투자_APP_Secret_Key
```

| 변수 | 값·역할 |
| --- | --- |
| `TRADING_ENV` | 필수. 과제 실행은 `mock` |
| `NH_APP_KEY`, `NH_APP_SECRET` | NH 시세·계좌 조회·모의 주문에 필요. 백테스트의 과거 분봉 조회에도 필요 |

인증정보는 로컬 `backend/.env`에만 저장. 실제 값이 있는 `.env`·키·토큰·계좌 식별정보는 제출 대상에서 제외.

### 2-4. 실행

**터미널 1 — 백엔드**

```bash
cd backend
uv sync --locked
uv run uvicorn app.main:create_app --factory --reload
```

**터미널 2 — 프론트엔드**

```bash
cd frontend
npm ci
npm run dev
```

`uv sync --locked`·`npm ci`는 최초 설치 또는 잠금 파일 변경 시에만 실행.

브라우저에서 [http://127.0.0.1:5173](http://127.0.0.1:5173)에 접속하면 모의매매·백테스트 화면이 표시됨(포트가 사용 중이면 Vite 터미널에 표시된 주소 사용).

### 2-5. 화면에서 실행

**백테스트 (프로그램 내부 시뮬레이션)**

- 메뉴 **백테스트**에서 전략·기간·초기자금·슬리피지를 정해 실행.
- 기간: 종료일은 오늘 이전, 최대 366일.
- 슬리피지: 0~20틱.
- NH 과거 분봉을 조회해 프로그램 안에서 체결을 계산. 모의계좌에는 주문하지 않음.
- 봉 마감 신호는 다음 봉 시가에 전량 체결.
- 체결마다 슬리피지와 수수료 반영.
- 증거금·주문가능수량 제한은 미적용.

**모의매매 (NH 모의계좌 주문)**

- 메뉴 **모의매매**에서 전략을 고르고 **운용 시작**.
- 해당 종목에 기존 포지션·미체결이 있으면 시작 거부.
- 시작 이후 새로 완성된 당일 3분봉부터 판단.
- **운용 종료** 시 해당 운용의 미체결 취소·보유분 청산.
- 운용 시작과 취소·청산은 모의계좌에 실제로 주문을 전송.
- 주문 접수와 체결을 구분해 확인.

### 2-6. 실행 기록

- 저장 위치: `backend/runs/<전략 id>/<backtest|paper>/<실행 일시>/`
- `meta.json`: 실행 조건·파라미터·상태
- `result.json`: 최종 요약
- `journal/YYYY-MM-DD.jsonl`: 판단·주문·체결·거래·이벤트
- `backtest`는 내부 시뮬레이션, `paper`는 NH 모의계좌 운용 기록.
- 제출 실행 확정 후 해당 폴더를 `results/<전략 id>/<모드>/<실행 일시>/`로 복사.
- 복사 전 키·계좌 식별정보가 없는지 확인.

실행이 안 되면 `backend/.env`(`TRADING_ENV=mock`, 키 앞 `#` 제거)와 국내 **모의투자용** 키 여부부터 확인. NH API 오류는 [API 오류 확인·질문·제보 안내](../docs/support-guide.md)에 따라 기록.

## 3. 전략과 매매 계획

“무릎에서 사고, 어깨에서 판다.”

삼성전자선물 역매매 전략은 저점 부근에서 반등하면 매수 포지션을, 고점 부근에서 되밀리면 매도 포지션을 연다. 고저점 이탈 후 복귀를 확인하고, 반대쪽 고저점까지의 가격 차이를 수익 기회로 삼는다. 목표까지 최소 3틱이 남아 있을 때 진입한다.

### 3-1. 대상 상품

대상은 삼성전자선물 2026년 11월물이다. 만기 접근에 따라 거래량과 변동성이 커질 것으로 예상했고, 이 과정에서 생기는 장중 가격 움직임을 매매 기회로 삼고자 했다.

| 항목 | 내용 |
| --- | --- |
| 전략 이름 | 삼성전자선물 역매매 전략 |
| 대상 종목 | 삼성전자선물 2026년 11월물 (`A116B000`) |
| 적용 호가 단위 | 500원 |
| 거래승수 | 10 |
| 1계약의 1틱 가치 | 5,000원 = 500원 × 10 |
| 진입당 수량 | 5계약 |
| 5계약의 1틱 손익 | 25,000원 |

| 신호 판단 | 완성된 3분봉 |

### 3-2. 전략 선정 이유

이미 오른 가격을 따라 매수하거나 내린 가격을 따라 매도하는 데 대한 부담에서 출발했다. 고저점을 넘어선 가격이 그 방향을 유지하지 못하고 돌아오는 움직임에 주목했다.

핵심 가설은 최근 저점을 터치한 뒤 올라선 가격이 반대쪽 고점으로, 최근 고점을 터치한 뒤 내려온 가격이 반대쪽 저점으로 움직일 수 있다는 것이다. 기준 가격 안쪽으로 복귀하고 다음 봉에서도 그 상태를 유지하면 진입한다. 반전의 첫 움직임을 확인하는 이 절차가 ‘무릎’과 ‘어깨’를 매매 규칙으로 옮긴 부분이다.

거래 방향은 가격으로 정하고, 거래량은 진입 조건으로 사용한다.

### 3-3. 지표 설정

**3분봉과 앞뒤 각 2봉의 고저점**을 사용한다. 작은 흔들림에 반응하는 빈도를 줄이면서 장중 방향 전환을 포착하려는 선택이다. 가운데 봉을 포함한 5개 봉을 비교하며, 가운데 봉 마감 후 뒤쪽 2개 봉이 완성되는 6분 뒤에 고저점을 확정한다.

**고점**은 가운데 봉의 고가가 앞쪽 2개 봉의 고가 이상이고 뒤쪽 2개 봉의 고가보다 높을 때 인정한다. **저점**은 가운데 봉의 저가가 앞쪽 2개 봉의 저가 이하이고 뒤쪽 2개 봉의 저가보다 낮을 때 인정한다. 후보 봉이 시작되기 전에 확정된 값만 기준으로 사용한다.

이후 다음 봉을 확인하여 복귀가 유지되는지 판단한다. 매수는 다음 봉도 기준 저점 위에서, 매도는 기준 고점 아래에서 마감해야 한다.

**거래량**은 확인 봉과 직전 10개 봉의 평균을 비교한다. 최근 30분을 비교 기준으로 삼고, 확인 봉은 평균에서 제외한다. 평균의 0.5배 이상일 때 진입을 허용해 거래활동이 적은 신호를 걸러낸다.

**신호와 목표 갱신**은 3분봉으로 판단한다. 손절·목표 도달은 실시간 가격으로 감시하고, 백테스트에서는 관측 1분봉의 가격 경로로 재현한다. 가격 도달에 따른 청산은 다음 3분봉 마감까지 기다리지 않는다.

### 3-4. 매매 규칙

매수와 매도는 아래 조건을 모두 충족해야 한다. 기준 고점과 저점이 모두 있어야 하며, 기준 고점은 기준 저점보다 높아야 한다.

| 항목 | 매수 | 매도 |
| --- | --- | --- |
| 후보 발생 | 봉 저가가 기준 저점 이하이고 종가가 기준 저점보다 높음 | 봉 고가가 기준 고점 이상이고 종가가 기준 고점보다 낮음 |
| 다음 봉 확인 | 바로 다음 연속 봉의 종가가 기준 저점보다 높음 | 바로 다음 연속 봉의 종가가 기준 고점보다 낮음 |
| 거래량 확인 | 확인 봉 거래량이 직전 10봉 평균의 0.5배 이상 | 확인 봉 거래량이 직전 10봉 평균의 0.5배 이상 |
| 첫 목표 | 후보 봉 시작 전에 확정된 최근 고점 | 후보 봉 시작 전에 확정된 최근 저점 |
| 손절 기준 | 진입 기준 저점 − 1,500원 | 진입 기준 고점 + 1,500원 |
| 진입 직전 가격 | 손절보다 높고 목표보다 낮음 | 목표보다 높고 손절보다 낮음 |
| 최소 목표거리 | 목표 − 관측 가격이 1,500원 이상 | 관측 가격 − 목표가 1,500원 이상 |

확인 봉에서는 새 후보를 만들지 않는다. 확인 봉 마감 직후 첫 1분 구간에서 처음 관측한 가격으로 진입 조건을 한 번 검사하고, 충족하면 5계약을 시장가로 주문한다. 조건 미충족이나 시한 경과 시 해당 신호를 폐기한다.

예를 들어 매수 목표가 225,000원이면 관측 가격 223,500원은 목표거리 3틱 조건을 충족한다. 224,000원은 2틱만 남으므로 제외한다.

**수량과 추가 진입 :** 새 신호가 확인되면 같은 방향으로 5계약씩 추가 진입하며, 청산 후 재진입도 허용한다. 보유 중 반대 방향 후보는 건너뛰고, 반대 신호로 포지션을 줄이거나 뒤집지 않는다. 같은 봉에서 양방향 후보가 발생하거나 이전 주문이 처리 중이면 진입하지 않는다.

**목표와 손절 :** 진입분마다 따로 관리한다. 새로운 반대쪽 고저점이 확정돼 가격이 바뀌면 목표를 갱신하고, 손절가는 유지한다. 갱신 시 완성 봉 종가가 이미 새 목표에 도달했거나 지났으면 시장가 청산을 요청한다. 실시간 가격이 목표나 손절에 닿으면 해당 진입분을 시장가로 청산하며, 두 조건을 동시에 충족하면 손절을 우선한다. 이미 청산 주문이 처리 중인 진입분에는 중복 주문을 내지 않는다.

**당일 마감 :** 15:24부터 신규·추가 진입을 중단하고 후보와 진입 대기를 폐기한다. 미체결 주문을 취소하되 청산 주문의 잔여 수량은 다시 청산 요청한다. 보유분의 손절·목표 관리는 계속한다. 15:30부터 미체결 주문을 취소하고 잔여 포지션의 전량 시장가 청산을 요청한다. 최종거래일에는 신규 진입 없이 잔여분을 청산하며, 최종거래일을 확인하지 못해도 신규 진입을 막는다.

**자료와 주문 유효성 :** 당일 마지막 연속 구간의 완성 봉을 사용하고, 공백 이전 이력은 지표 계산에서 제외한다. 고저점이나 직전 10봉이 부족하거나 평균 거래량이 0이면 진입하지 않는다. 진입 주문 유효기간은 1봉이며, 이후 미체결 잔량을 취소한다.

### 3-5. 주요 설계와 근거

**최소 목표거리 3틱은 거래 기회와 비용 내성을 고려해 선택했다.** 사전 비교에서는 목표까지 1~2틱만 남은 거래가 많아 비용 반영 후 성과가 약해졌다. 3틱과 4틱 조건 중 거래를 지나치게 줄이지 않으면서 비용 내성이 개선된 3틱을 채택했다.

**고정 5계약은 1억원 예산에서 한 번의 진입 규모를 조절하려는 선택이다.** 거래량에 따라 주문 규모까지 키우기보다, 일정한 수량으로 신호를 평가하는 쪽을 택했다. 거래량 비례 수량과 비교하면서 매매 조건과 수량 확대의 영향을 구분하고자 했다.

**거래량 0.5배는 거래 기회와 일별 손익 변동을 고려해 정했다.** 거래활동이 적은 구간의 일시적인 복귀를 걸러내려 했다. 초기 비교에서 필터 없음·0.5배·1배를 검토했고, 1배 조건은 손익 변동과 함께 수익 기회도 크게 줄여 0.5배를 선택했다.

**손절 폭 1,500원은 초기 비교 결과를 바탕으로 선택했다.** 복귀한 가격이 다시 기준선을 넘어 불리하게 움직이면 진입 근거가 약해졌다고 보았다. 1,000원과 1,500원을 비교한 결과, 초기 표본에서 손절 횟수가 적고 합계 손익이 높았던 1,500원을 채택했다.

**목표 갱신은 장중 가격 구조의 변화에 대응하기 위해 선택했다.** 목표 고정 방식도 비교했으며, 최초 목표를 유지하기보다 새로 형성된 가격대에 맞춰 보유분을 정리하는 쪽을 택했다.

**추가 진입은 보유 중에도 발생하는 매매 기회를 활용하기 위해 허용했다.** 같은 방향의 회복 신호가 반복되면 다시 가격 차이를 얻을 기회가 있다고 보았다. 기존 포지션이 있다는 이유만으로 새 신호를 제외하지 않도록 했다.

**당일 청산은 장중 전략의 보유 범위를 한정하기 위해 정했다.** 장 마감 전에 포지션을 정리해 야간과 다음 날 시초가 변동에 대한 노출을 줄이고자 했다.

### 3-6. 약점

강한 추세에서는 일시적인 복귀 뒤 기존 방향이 이어져 역방향 포지션이 손절될 수 있다. 다음 봉 확인을 기다리는 동안 목표까지의 거리도 줄어든다.

짧은 가격 차이를 거래하므로 수수료와 슬리피지의 영향이 크다. 시장가 체결가격은 검사한 가격과 달라질 수 있고, 목표 갱신으로 손실 상태에서 청산될 수도 있다. 손절도 진입가가 아닌 기준 고저점에서 정하므로 거래당 손실액이 다르다.

총보유량 상한과 일일 손실 한도는 없다. 5계약씩 추가 진입이 겹치면 보유량과 손실 노출이 함께 커진다.

## 4. 사용 API와 프로그램 구조

### 4-1. 구조

```text
브라우저(React) ──REST /api · WebSocket /ws──▶ 백엔드(FastAPI) ──▶ NH선물 Open API (모의)
                                                   │
                                                   ├─ 전략 코드 (backend/strategies/)
                                                   └─ 실행 기록 (backend/runs/)
```

- 모의매매와 백테스트가 같은 전략 코드를 호출. 전략은 완성된 3분봉을 받아 매수·매도·보유·건너뜀을 판단.
- 매매 실행은 백엔드가 관리. 프론트엔드는 조회와 실행 요청만 수행.
- 백테스트는 NH 과거 분봉을 조회해 프로그램 안에서 체결을 계산. 모의매매는 NH 모의계좌에 주문 전송.

### 4-3. 기록 형식

- 실행 1건 = 폴더 1개(`meta.json`·`result.json`·`journal/날짜.jsonl`). 한 줄이 한 사건이며 종류는 `decision`(판단)·`order`(주문)·`fill`(체결)·`trade`(진입부터 청산까지 1건)·`event`.
- 판단 기록(`decision`)에는 건너뛴 사유(`reason`)와 기준 고저점이 남음.
- 키·토큰·계좌번호 필드는 기록기가 저장 전에 제거.

## 7. 해석과 한계

### 7-1. 백테스트 결과 해석

**1) 결과의 부호가 슬리피지 1틱에 따라 바뀌었다.** 슬리피지 0틱에서는 순손익 +901,349원, 1틱에서는 -1,698,651원이다. 총손익 차이 2,600,000원은 체결 104건 × 1틱(25,000원)과 정확히 같다. 수수료는 두 실행에서 같다(98,651원). 슬리피지로 매수는 높은 가격에, 매도는 낮은 가격에 체결되어 한 거래의 진입·청산 수수료 변화가 서로 상쇄되기 때문이다. 이 전략의 이익은 슬리피지 0틱이라는 낙관적 가정에서만 나왔고, 1틱 가정에서는 손실이다.

**2) 최소 목표거리 3틱이 왕복 비용을 감당하지 못했다.** 목표 도달 32건의 건당 총손익은 0틱에서 +3.16틱, 1틱에서 +1.16틱이다. 진입과 청산 각 1틱씩 왕복 2틱이 빠지면서 3틱 목표의 이익이 약 1틱으로 줄었다. 반면 손절 17건의 건당 총손익은 -3.59틱에서 -5.59틱으로 커졌다. 3-5절에서 비용 내성을 근거로 3틱을 골랐으나, 슬리피지 1틱 가정에서는 그 근거가 충분하지 않았다.

**3) 손익비와 승률의 관계가 달라졌다.** 0틱에서 손익분기 승률은 52.6%이고 실제 승률은 63.5%로 넘었다. 1틱에서는 손익분기 승률이 68.4%로 올라간 반면 실제 승률은 44.2%였다. 이 전략은 평균 이익이 평균 손실보다 작은 구조(0틱에서도 75,385원 대 83,492원)라 높은 승률에 의존한다.

**4) 거래가 하루에 몰려 있고, 표본이 작다.** 0틱 순손익 901,349원 중 2026-10-23 하루가 +360,658원으로 40%를 차지한다. 가장 나쁜 날은 2026-10-16(-134,216원)이다. 18거래일 중 3일은 거래가 없었고, 전체 거래는 52건이다. 이 결과로 전략의 우열을 판단하기는 어렵다.

**5) 3틱 목표거리 조건이 거래를 가장 많이 줄였다.** 확인을 마친 148건 중 70건(47%)이 목표거리 3틱 미만으로 제외되었고, 26건은 진입 가격이 손절·목표 범위를 벗어나 제외되었다. 후보 261건 중 진입은 52건(20%)이다.

**6) 청산은 대부분 설계한 규칙대로 나갔다.** 청산 사유는 목표 도달 32건, 손절 17건, 당일 청산 3건이다. 15:30 당일 청산은 3건에 그쳐 대부분의 포지션이 당일 안에 목표나 손절로 정리되었다. 보유 시간 중앙값은 19분이다.

**7) 추가 진입으로 노출이 커진 순간이 있었다.** 같은 방향 신호가 겹쳐 최대 3개 진입분(15계약)을 동시에 보유했다. 총보유량 상한이 없다는 3-6절의 약점이 실제 기록에서 확인되었다.

### 7-2. 백테스트 가정과 한계

- 시장가 주문은 전량 즉시 체결로 가정한다. 호가 잔량·부분체결·미체결은 반영하지 않는다.
- 슬리피지는 체결가에 반영한다. 두 실행에서 진입 시각과 청산 사유가 모두 같으므로, 이 백테스트에서는 슬리피지가 이후 진입 조건 검사와 목표·손절 도달 판정에 영향을 주지 않는다. 실제 체결에서 불리한 체결이 이후 신호와 포지션을 바꿀 수 있는 효과는 반영되지 않는다.
- 수수료는 슬리피지를 반영한 체결가 기준으로 계산한다. 매수와 매도의 변화가 상쇄되어 두 실행의 수수료 합계는 같다.
- 장중 가격은 1분봉 안에서 시가 → 불리한 극단 → 유리한 극단 → 종가 순서로 움직였다고 가정한다. 한 분 안에서 목표와 손절이 모두 닿으면 손절이 먼저 일어난 것으로 처리되어 결과가 불리한 쪽으로 기운다. 실제 순서는 알 수 없다.
- 누락된 1분봉은 합성하지 않는다.
- 증거금과 주문가능수량을 제한하지 않는다. 최대 15계약 보유가 실제 계좌에서 가능한지는 확인하지 않았다.
- 백테스트는 NH 모의계좌 체결이 아니다. 모의계좌 체결과의 차이는 모의매매 결과 확정 후 비교한다.

### 7-3. 예상과 다른 점

- 3-5절의 사전 비교에서는 3틱 조건이 비용 내성을 개선한다고 보았으나, 슬리피지 1틱 가정에서는 손실이었다.
- 손익분기 승률이 가정에 따라 53%에서 68%까지 움직여, 승률만으로 전략을 평가하기 어렵다.

# 주차별 폴더 구조와 보고서 작성 안내

## 폴더 구조

`week01`~`week08`은 `.gitkeep`으로 준비. 해당 주차 작업 시 필요한 파일·폴더 생성.

```text
weekNN/
├── README.md          그 주의 보고서
├── 코드·설정 파일     실행 코드와 공유 가능한 설정 템플릿
├── results/           실행 근거 원본 데이터
└── screenshots/       실제 화면 캡처
```

주차별 Markdown 문서는 `README.md` 하나로 통합. 실행 방법·결과·캡처 설명도 해당 문서에 작성.

## 보고서 작성 순서

1. **과제 요약** — 요구사항과 수행 내용.
2. **실행 방법** — 설치·설정·재현 절차, 설정 파일 템플릿, 실행 명령.
3. **전략과 매매 계획** — 대상 상품·월물, 진입·청산·손절 규칙과 근거.
4. **사용 API와 구조** — 사용한 API와 사용 위치, 프로그램 구성.
5. **실행 환경** — 모의계좌 주문·시뮬레이션 등 실제 환경, 실행 일시·구간.
6. **실행 결과** — 거래 표·손익·캡처(`screenshots/`)·근거 파일(`results/`).
7. **해석과 한계** — 손익 원인, 전략의 한계, 예상과 다른 점.
8. **오류 제보·개선·향후 계획** — 겪은 오류, 제보 내용, 다음에 개선할 사항.

## 작성 시 주의사항

- 수치는 `results/`의 원본 파일에서 읽은 값만 기재. 보고서 숫자와 원본 일치 확인.
- 주문 접수와 체결 구분. 시뮬레이션 체결을 모의계좌 체결로 표기하지 않음.
- 손실 결과도 그대로 기록·분석. 평가 관점은 과제 충족·동작 검증·분석·재현성.
- 인증정보·계좌 식별정보 가림.
